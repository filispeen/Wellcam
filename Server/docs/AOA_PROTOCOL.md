# Протокол AOA для ПК-клієнта

Режим "USB (AOA)" у WinCam Server. Телефон працює як USB-акцесуар (Android Open Accessory), ПК є USB-хостом. Режим розробника, USB debugging і `adb` не потрібні.

Телефон тільки передає. Потік байтів на bulk IN endpoint ПК ідентичний потоку TCP (Protocol v2), без додаткової обгортки.

## 1. Рядки акцесуара

Рядки, які ПК надсилає телефону, мають збігатися з `app/src/main/res/xml/accessory_filter.xml` і константами в `AoaTransport.kt`. Порівняння чутливе до регістру.

- manufacturer (index 0): `Filispeen`
- model (index 1): `WinCam`
- description (index 2): `WinCam Server`
- version (index 3): `1`
- uri (index 4): будь-який, наприклад `https://example.invalid`
- serial (index 5): будь-який, наприклад `0`

Телефон шукає акцесуар за manufacturer і model. Фільтр у manifest додатково перевіряє version.

## 2. Послідовність на боці ПК

1. Знайти телефон (його звичайні VID/PID) і відкрити пристрій через libusb.
2. GET_PROTOCOL: control transfer `bmRequestType=0xC0`, `bRequest=51`, `wValue=0`, `wIndex=0`, довжина 2. Відповідь: версія протоколу, u16 little-endian. Якщо 0, телефон не підтримує AOA.
3. Для кожного рядка 0..5: control transfer `bmRequestType=0x40`, `bRequest=52`, `wValue=0`, `wIndex=<індекс рядка>`, дані: рядок UTF-8 із завершальним нулем.
4. START: control transfer `bmRequestType=0x40`, `bRequest=53`, `wValue=0`, `wIndex=0`, без даних.
5. Телефон відключається і з'являється знову як VID `0x18D1`, PID `0x2D00` (accessory) або `0x2D01` (accessory + adb, якщо на телефоні ввімкнено ADB). Клієнт має приймати обидва PID і чекати появи пристрою до кількох секунд. Не вимагати `0x2D01`.
6. Відкрити новий пристрій, claim interface 0 (при `0x2D01` інтерфейс 1 це adb, його не чіпати).
7. Знайти на інтерфейсі bulk IN і bulk OUT endpoint.
8. Надіслати на bulk OUT hello: 4 байти ASCII `HELO` (насправді телефон реагує на будь-які байти). Телефон починає передачу тільки після hello.
9. Читати з bulk IN. Спочатку знайти в потоці послідовність `WCAM` + `0x02` + кодек 1 або 2 і відкинути все перед нею: у каналі можуть лишитися байти попереднього сеансу. Звідти йде заголовок і потік пакетів.

Hello можна надіслати повторно в будь-який момент: телефон скидає чергу, знову надсилає заголовок, config і чекає ключовий кадр. Це спосіб ресинхронізації. Обов'язково надсилай hello при кожному відкритті пристрою, бо закриття handle на ПК телефон не помічає: кабель лишається підключеним, акцесуар відкритим.

Якщо пристрій уже в accessory mode (`0x18D1:0x2D00/0x2D01`), кроки 1-5 пропускаються.

## 3. Формат даних

Потік байтів без додаткових заголовків AOA. Межі USB-транзакцій не відповідають межам пакетів Protocol v2: накопичуй байти в буфері й розбирай потік.

Заголовок, один раз після підключення, 14 байт big-endian:

- magic `WCAM` (4 байти)
- версія u8 (2)
- кодек u8 (1 H.264, 2 H.265)
- width u16, height u16, fps u16, rotation u16 (sensorOrientation)

Далі безперервно пакети:

- тип u8 (0 config, 1 frame)
- flags u8 (bit0 keyframe, bits 1-2 phone orientation in clockwise quarters of 90 degrees from portrait: 0 portrait, 1 rotated right, 2 upside down, 3 rotated left; other bits reserved, receivers that do not know the orientation bits ignore them)
- pts u64 (мкс)
- size u32
- payload `size` байт

На кожен hello телефон надсилає заголовок, потім config, потім кадри починаючи з ключового.

## 4. Читання через libusb

- Розмір буфера читання кратний 512, наприклад 16384 або 65536.
- Таймаут читання обов'язковий. `LIBUSB_ERROR_TIMEOUT` не помилка, а відсутність даних: повторюй. Дані, що встигли надійти, повертаються в `transferred` навіть при таймауті, їх треба додати до буфера.
- Помилки `LIBUSB_ERROR_NO_DEVICE` і `LIBUSB_ERROR_IO` означають відключення кабелю або зупинку сервера. Закрий handle і повернись до пошуку пристрою.
- Після hello ПК більше нічого не пише в телефон. Подальші дані на bulk OUT телефон читає: кожна порція трактується як новий hello.

## 5. Windows

libusb на Windows потребує драйвера WinUSB на пристрої. Встановлюється через Zadig.

- Для кроків 2-4 драйвер потрібен на самому телефоні в його звичайному режимі. Це замінює драйвер MTP для цього телефона, поки не відкотити його в диспетчері пристроїв. Це головна практична ціна режиму на Windows.
- Для кроків 5-7 потрібен WinUSB на `18D1:2D00` (і `18D1:2D01`, якщо використовуєш ADB). Встановлюється один раз для кожного PID. Для `2D01` вибирай інтерфейс 0 (accessory). Без цього libusb повертає "Entity not found".
- "Access denied" при відкритті телефона на кроці 2 зазвичай означає, що пристрій тримає `adb.exe`. Виконай `adb kill-server`.
- Після вийнятого кабеля або вимкнення телефона `read` на ПК завершується помилкою `Pipe error` (errno 32). Це сигнал закрити пристрій і шукати його знову. Телефон після повторного підключення знову проходить розділ 2.

## 6. Поведінка на телефоні

1. У WinCam Server вибери "USB (AOA)" і натисни Start server. Статус: "Waiting for USB host".
2. Запусти ПК-клієнт. Після START телефон перемикається в accessory mode, система показує запит дозволу USB-акцесуара (екран має бути розблокований). Підтверди.
3. Після hello від ПК статус "Connected: USB host". Заголовок і config надсилаються автоматично.
4. Якщо кабель вийнятий, статус на телефоні "Client disconnected". Якщо ПК просто закрив пристрій, телефон за 3 секунди переходить у той самий стан (див. п. 5). Нова сесія ПК-клієнта починається з hello і ресинхронізації за `WCAM`.
5. Якщо ПК не читає понад 3 секунди або черга перевищила 8 МБ, телефон не закриває акцесуар, а скидає чергу, зупиняє передачу і показує "Client disconnected". Кодер не блокується. Нова сесія ПК-клієнта починається з hello.

## 7. Тестування без ПК-клієнта

`docs/aoa_test.py` виконує розділ 2, читає потік і раз на секунду друкує кадри, ключові кадри та Mbps.

1. `pip install pyusb`. На Windows потрібен `libusb-1.0.dll` у PATH і WinUSB із розділу 5.
2. Запусти сервер на телефоні в режимі "USB (AOA)".
3. Перемикання з нуля: `python docs/aoa_test.py --vid <VID телефона hex> --pid <PID телефона hex>`. VID/PID видно в диспетчері пристроїв або в Zadig.
4. Якщо телефон уже в accessory mode, аргументи не потрібні: `python docs/aoa_test.py`.
5. Обмеження скрипта: pyusb губить дані при таймауті читання посеред передачі. Для продакшн-клієнта використовуй `transferred` з libusb.

## 8. Відкриті рішення

- Керуючий канал мінімальний: єдине повідомлення хост, телефон це hello на bulk OUT. Формат Protocol v2 не змінений.
- `0x2D01` підтримується клієнтом, але не рекомендований як обов'язковий режим: він працює лише при ввімкненому ADB.
